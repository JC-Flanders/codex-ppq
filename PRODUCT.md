# 402 Paid Endpoint Landing Pages

Draft project context for a series of one-page landing pages promoting paid services that use HTTP 402 payment protocols, including x402, L402, and Machine Payments Protocol.

register: brand

## Purpose

Help humans, developers, and agents discover useful paid endpoints, understand what each endpoint does, and decide whether to call it.

The page should make the endpoint feel concrete: what job it performs, what it costs, what input it needs, what output it returns, which payment protocol it supports, and how a user or agent can try it.

## Primary Audiences

- Developers evaluating whether a paid endpoint solves a real task.
- AI and agent builders looking for payable tools, APIs, or MCP services.
- Operators and product people checking whether there is market interest in 402-enabled services.
- Search and LLM crawlers that need clean, factual, machine-readable descriptions.

## Success Signals

- Organic impressions and clicks for task-oriented queries, not only protocol keywords.
- Clicks on "try endpoint", docs, code examples, and provider links.
- Paid calls or successful test calls from the page.
- Agent usage from documented endpoint metadata.
- Clear evidence of which categories and endpoint jobs attract interest.

## Strategic Principles

- Lead with the useful job, not the protocol.
- Treat the endpoint as the product. The protocol is the access and payment layer.
- Show price, input, output, limits, provider, and freshness near the top.
- Make the first fold useful even if the visitor never scrolls.
- Keep Alby-related copy short, concrete, product-led, and focused on what users can do.
- Explain payment mechanics only after the user understands the endpoint value.
- Make wallet permissions, budgets, spending limits, and revocation obvious when a page involves wallet connection or agent spending.
- Use protocol-specific facts carefully. x402, L402, and MPP are evolving quickly.

## Anti-Goals

- Generic crypto marketing pages.
- Protocol-first pages that bury the endpoint job.
- Long essays with no runnable examples.
- SEO pages made only for crawlers with thin or duplicated content.
- Hiding indexable landing page content behind a payment wall.
- Making agent payments sound unrestricted or unsafe.
- Overusing "AI agent" language when the endpoint is useful to normal developers too.

## Terminology

- Use "endpoint" for the monetized route or callable service.
- Use "paid endpoint" or "pay-per-use endpoint" for the category.
- Use "protocol" for x402, L402, or MPP.
- Use "call the endpoint" for the action developers and agents take.
- Use "price per request", "price per result", or "session price" as applicable.
- Avoid treating "402" as self-explanatory. Spell out "HTTP 402 Payment Required" where helpful.
